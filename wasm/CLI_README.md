# NEC++ WASM Command-Line Interface

This document describes how to use the NEC++ WASM command-line tool (`nec_wasm.js`) for running antenna simulations from the terminal using Node.js.

## Overview

The `nec_wasm.js` script is a Node.js command-line wrapper for the NEC++ WebAssembly module. It parses standard NEC input files (`.nec`) and produces output files compatible with the native C++ `nec2++` binary. This allows you to run electromagnetic antenna simulations without compiling native code.

Key features:
- Parses standard NEC-2 format input files
- Produces output compatible with the C++ version
- Supports all common NEC cards (GW, FR, EX, GN, RP, XQ, etc.)
- Multiple output formats: plain text, CSV, and XML
- Gain-only mode for quick antenna comparisons
- Built-in benchmark mode

## Prerequisites

1. **Node.js** (v14 or later recommended)
   ```bash
   node --version  # Verify installation
   ```

2. **Built WASM module** - The following files must exist in the `wasm/` directory:
   - `necpp.js` - JavaScript glue code
   - `necpp.wasm` - WebAssembly binary

## Building the WASM Module

Before using the CLI, you must build the WASM module using Emscripten.

### Step 1: Install Emscripten SDK

```bash
# Clone the Emscripten SDK
git clone https://github.com/emscripten-core/emsdk.git
cd emsdk

# Install and activate the latest version
./emsdk install latest
./emsdk activate latest
```

### Step 2: Activate Emscripten Environment

**Important:** You must activate the Emscripten environment in every new terminal session before building:

```bash
source /path/to/emsdk/emsdk_env.sh
```

Verify the installation:
```bash
em++ --version
```

### Step 3: Build the WASM Module

```bash
cd wasm
make
```

This produces:
- `necpp.js` - JavaScript glue code for the WASM module
- `necpp.wasm` - The compiled WebAssembly binary

To rebuild from scratch:
```bash
make clean && make
```

## CLI Usage

### Basic Syntax

```bash
node nec_wasm.js [options]
```

### Command-Line Options

| Option | Description |
|--------|-------------|
| `-i <file>` | Input NEC file (required, unless using -b or -v) |
| `-o <file>` | Output file (optional; defaults to `<input>.outwasm`) |
| `-h`, `--help` | Print help message and exit |
| `-v`, `--version` | Print version number and exit |
| `-s` | Print results to standard output (stdout) |
| `-c` | Output in CSV format (use with `-s`) |
| `-x` | Output in XML format (use with `-s`) |
| `-g` | Gain-only mode: print maximum gain to stdout |
| `-b` | Run NEC++ benchmark (no input file required) |

### Output File Naming

If `-o` is not specified, the output file is automatically generated by replacing the `.nec` extension with `.outwasm`:
- Input: `antenna.nec` -> Output: `antenna.outwasm`

## Examples

### Basic Simulation

Run a simulation and write output to a file:

```bash
node wasm/nec_wasm.js -i testharness/data/example1.nec -o output.out
```

### Custom Output File

```bash
node wasm/nec_wasm.js -i antenna.nec -o results/my_antenna.out
```

### Print to Standard Output

Display results directly in the terminal:

```bash
node wasm/nec_wasm.js -i antenna.nec -s
```

### CSV Format Output

Generate machine-readable CSV output (useful for data processing):

```bash
node wasm/nec_wasm.js -i antenna.nec -s -c
```

CSV output includes sections for:
- Antenna input parameters (impedance, current, power)
- Segment currents
- Radiation pattern data

### XML Format Output

Generate structured XML output:

```bash
node wasm/nec_wasm.js -i antenna.nec -s -x
```

### Gain-Only Mode

Quickly get the maximum gain value for antenna comparisons:

```bash
node wasm/nec_wasm.js -i antenna.nec -g
# Output: 2.1456
```

This mode is useful for:
- Scripted antenna optimization
- Quick performance comparisons
- Automated testing

### Benchmark Mode

Test your system's NEC++ performance:

```bash
node wasm/nec_wasm.js -b
```

Example output:
```
The nec2++ benchmark.
nec2++ version 1.7.5-wasm [WASM/Node.js]

Your computer's score is: 15.42 NEC's
```

### Version Information

```bash
node wasm/nec_wasm.js -v
# Output: nec2++ 1.7.5-wasm [WASM/Node.js]
```

### Help

```bash
node wasm/nec_wasm.js -h
```

Output:
```
usage: nec2++ [-i<input-file-name>] [-o<output-file-name>]
       -g: print maximum gain to stdout.
       -b: Perform NEC++ Benchmark.
       -s: print results to standard output.
       -c: print results in comma-separated-value (CSV) format,
           this option is used in conjunction with (-s) above.
       -x: print results in XML format,
           this option is used in conjunction with (-s) above.
       -h: print this usage information and exit.
       -v: print nec2++ version number and exit.
```

## Comparison with C++ CLI

The WASM CLI (`nec_wasm.js`) accepts the same command-line options as the native C++ binary (`nec2++`):

| Feature | C++ (`./nec2++`) | WASM (`node nec_wasm.js`) |
|---------|------------------|---------------------------|
| Input file | `-i file.nec` | `-i file.nec` |
| Output file | `-o file.out` | `-o file.out` |
| Stdout output | `-s` | `-s` |
| CSV format | `-c` | `-c` |
| XML format | `-x` | `-x` |
| Gain only | `-g` | `-g` |
| Benchmark | `-b` | `-b` |
| Version | `-v` | `-v` |
| Help | `-h` | `-h` |

This compatibility allows you to swap between implementations for testing or deployment without changing your workflow.

**Example - equivalent commands:**

```bash
# C++ version
./nec2++ -i testharness/data/example1.nec -o output.outcpp

# WASM version
node wasm/nec_wasm.js -i testharness/data/example1.nec -o output.outwasm
```

## Testing

### Quick Test (All 41 Test Files)

Run all tests using the provided script from the repository root:

```bash
bash test_all_wasm.sh
```

This script runs the WASM CLI on all test files in `testharness/data/` and reports pass/fail status.

### Detailed Testing with Makefile

The `testharness/Makefile.wasm` provides comprehensive testing capabilities:

```bash
cd testharness

# Run WASM tests only
make -f Makefile.wasm test_wasm

# Run C++ tests only
make -f Makefile.wasm test_cpp

# Compare WASM vs C++ outputs (runs both tests first)
make -f Makefile.wasm compare

# Compare a single file
make -f Makefile.wasm compare_one FILE=example1

# Clean test outputs
make -f Makefile.wasm clean

# Show help
make -f Makefile.wasm help
```

### Manual Output Comparison

Compare specific output files using the comparison script:

```bash
python3 testharness/nec_compare.py file1.outcpp file2.outwasm --tolerance 1e-5
```

### Test File Location

Test input files are located in `testharness/data/` and include:
- Simple dipoles (`example1.nec`, `example3.nec`)
- Yagi antennas (`yagi.nec`)
- Patch antennas (`patch*.nec`)
- Helical antennas (`helix*.nec`)
- Various ground conditions
- Different excitation types

## Supported NEC Cards

The WASM CLI supports the following NEC input cards:

### Geometry Cards
- `GW` - Wire specification
- `SP` - Surface patch
- `SC` - Surface patch continuation
- `GX` - Reflection (symmetry)
- `GM` - Geometry move/rotate
- `GE` - Geometry end

### Program Cards
- `FR` - Frequency specification
- `EX` - Excitation source
- `GN` - Ground parameters
- `LD` - Loading (impedance)
- `TL` - Transmission line
- `NT` - Network
- `EK` - Extended thin-wire kernel
- `KH` - Kernel handling
- `GD` - Ground description
- `RP` - Radiation pattern request
- `NE` - Near electric field
- `NH` - Near magnetic field
- `PT` - Print currents
- `PQ` - Print charges
- `CP` - Coupling
- `XQ` - Execute
- `EN` - End of file

### Comment Cards
- `CM` - Comment
- `CE` - Comment end

## Troubleshooting

### "Error: Input file (-i) is required"

You must specify an input file with `-i`:
```bash
node wasm/nec_wasm.js -i your_antenna.nec
```

### "Cannot find module './necpp.js'"

The WASM module hasn't been built. Build it first:
```bash
cd wasm && make
```

### "em++: command not found"

Emscripten is not activated. Activate it:
```bash
source /path/to/emsdk/emsdk_env.sh
```

### Simulation hangs or times out

Some antenna configurations (especially with plane wave excitation) may cause very long computation times. Try:
- Reducing the number of segments
- Simplifying the geometry
- Using a coarser radiation pattern resolution

### Results differ from C++ version

Small numerical differences (within 1e-5 relative tolerance) are expected due to:
- Different floating-point handling in WASM
- Output format differences

For validation, use the comparison tools:
```bash
python3 testharness/nec_compare.py cpp_output.out wasm_output.out --tolerance 1e-5
```

## Performance Notes

- WASM uses a built-in matrix solver (no LAPACK dependency)
- Performance is typically 3-10x slower than native C++ with optimized BLAS/LAPACK
- Memory is limited to 2GB maximum
- Single-threaded execution only

For large simulations (>1000 segments), consider using the native C++ build for better performance.
